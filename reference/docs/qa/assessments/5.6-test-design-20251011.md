# Test Design: Story 5.6 - Cleanup and Rename Frontend

**Date:** 2025-10-11
**Designer:** Quinn (Test Architect)
**Story:** 5.6 - Cleanup Admin-UI and Rename Frontend
**Type:** Brownfield Cleanup / Infrastructure

---

## Test Strategy Overview

This is an **infrastructure refactoring story** with minimal functional changes. Testing strategy prioritizes:
- Build pipeline integrity
- Deployment process validation
- Git history preservation
- Configuration correctness

### Test Distribution

- **Total test scenarios:** 26
- **Unit tests:** 2 (8%)
- **Integration tests:** 16 (61%)
- **E2E tests:** 8 (31%)

### Priority Distribution

- **P0 (Critical):** 12 scenarios (46%)
- **P1 (High):** 10 scenarios (38%)
- **P2 (Medium):** 4 scenarios (16%)

### Test Execution Strategy

1. **Pre-cleanup verification** (P0 integration tests) - Baseline working system
2. **Folder operations** (P0 integration tests) - Git operations correct
3. **Build process** (P0 integration + E2E tests) - Pipeline works
4. **Deployment verification** (P0 E2E tests) - Full deployment cycle
5. **UI improvements** (P1 integration/E2E tests) - Minor enhancements work
6. **Documentation** (P2 integration tests) - No broken references

## Summary and Recommendations

### Test Strategy Rationale

This story is **infrastructure-focused** with minimal functional changes. The test strategy appropriately:
- **Emphasizes integration tests (61%)** - Validates build and config changes
- **Includes critical E2E tests (31%)** - Ensures deployment pipeline works
- **Minimal unit tests (8%)** - Only for new UI logic components

### Key Insights

1. **Risk is in the pipeline, not the code** - Focus on build/deploy validation
2. **Git history preservation is compliance-critical** - Explicit tests required
3. **Reference cleanup is error-prone** - Comprehensive grep-based validation needed
4. **UI improvements are low-risk** - Standard component testing sufficient

### Execution Recommendation

**Phase 1 (Pre-cleanup):** Establish baseline - 15 minutes
**Phase 2-6 (Core changes):** Critical path validation - 45 minutes
**Phase 7-9 (Cleanup):** Reference and doc validation - 30 minutes

**Total estimated test execution time:** ~90 minutes for full validation

### Test Automation Priority

1. **Automate first:** All P0 build and deployment tests (critical path)
2. **Automate second:** P1 grep-based reference checks (fast ROI)
3. **Keep manual:** P2 documentation review (low frequency)
