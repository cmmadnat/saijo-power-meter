## Detailed Risk Register

### Medium Risks (Score 4)

#### DATA-001: Field Annotation Errors

**Score: 4 (Medium)**
**Probability:** Medium (2) - Developer may copy-paste with errors
**Impact:** Medium (2) - Would cause Firestore serialization/deserialization failures

**Description:**
Incorrect @JsonProperty or @PropertyName annotations on the 24 new fields could cause:
- Firestore documents to have wrong field names (breaking persistence)
- REST API to use wrong JSON property names (breaking API contract)
- Data loss or corruption if fields don't map correctly

**Affected Components:**
- OutdoorUnitStd.java (24 new fields)
- Firestore collection: outdoor_unit_standards
- REST API endpoints: /api/v1/function-test/outdoor/std

**Mitigation Strategy:**

**Type:** Preventive

**Actions:**
1. Follow exact pattern from Stories 5.1 and 5.2:
   ```java
   @JsonProperty("field_name_snake_case")  // JSON snake_case
   @PropertyName("fieldNameCamelCase")      // Firestore camelCase
   private String fieldNameCamelCase;       // Java camelCase
   ```
2. Use field mapping table from story Dev Notes (lines 481-506)
3. Implement integration tests for Firestore round-trip
4. Verify JSON serialization matches API specification

**Testing Requirements:**
- **5.3-INT-001**: Firestore serialization test (verify all 24 fields serialize to camelCase)
- **5.3-INT-002**: Firestore deserialization test (verify all 24 fields deserialize correctly)
- **5.3-INT-004**: REST API POST test (verify JSON snake_case accepted)
- **5.3-INT-005**: REST API GET test (verify JSON snake_case returned)

**Residual Risk:** Low - After proper testing and following established patterns

**Owner:** Dev
**Timeline:** Before commit
