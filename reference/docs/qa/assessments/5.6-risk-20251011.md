## High Priority Risks (Score 6)

### 1. TECH-001: Git History Loss During Rename

**Score: 6 (High)**
**Probability**: Medium (2) - Possible if `git mv` not used correctly or atomic commit approach violated
**Impact**: High (3) - Loss of commit history makes debugging and code archaeology extremely difficult

**Description**:
Renaming `lovable-project-7aec971c/` to `frontend/` using manual file operations or incorrect git commands could result in Git treating this as a delete+add operation rather than a rename, losing valuable commit history.

**Affected Components**:
- `lovable-project-7aec971c/` (entire directory)
- Git repository history
- Developer workflow and git blame functionality

**Mitigation Strategy**: Preventive
**Actions**:
1. **MUST use `git mv lovable-project-7aec971c frontend`** - Never use manual file operations
2. Verify rename detection with `git status` immediately after - should show "renamed:" not "deleted:" + "new file:"
3. Use single atomic commit for rename and all configuration updates
4. Test git log and git blame on renamed files to verify history preservation
5. Create git tag `pre-frontend-rename` before changes as safety checkpoint

**Testing Requirements**:
- Manual verification: `git status` shows rename detection
- Manual verification: `git log frontend/src/App.tsx` shows full commit history
- Manual verification: `git blame frontend/package.json` attributes to original authors

**Residual Risk**: Very Low - Git mv is reliable when used correctly; history preservation virtually guaranteed

**Owner**: Dev
**Timeline**: First task in implementation sequence

**Impact**: High (3) - Broken build pipeline blocks all deployments and CI/CD workflows

- `lovable-project-7aec971c/cypress.config.ts` → `frontend/cypress.config.ts`
- Maven build process
- Cloud Run deployment pipeline

**Mitigation Strategy**: Preventive + Detective
**Actions**:
1. Create checklist of all files requiring updates (already documented in story)
2. Use search to find all references: `grep -r "lovable-project-7aec971c" .`
3. Update all references in single atomic commit with rename
4. **MUST run full build immediately**: `./mvnw clean package`
5. **MUST run deployment script dry-run**: `./deploy.sh staging`
6. Verify all artifacts generated correctly in expected locations

**Testing Requirements**:
- Build test: `cd smart-factory-backend && ./mvnw clean package` succeeds
- Artifact verification: `frontend/dist/` exists and contains built assets
- Artifact verification: `smart-factory-backend/target/classes/META-INF/resources/` contains frontend assets
- Integration test: Full deploy.sh execution to staging environment
- E2E test: Deployed application serves frontend correctly

**Residual Risk**: Low - Comprehensive build testing catches configuration errors before production

**Owner**: Dev
**Timeline**: Before deployment to any environment
