### Field Mapping Pattern (CRITICAL - Follow Exactly)

The existing codebase uses a **specific annotation pattern** for field mapping:

```java
@JsonProperty("field_name_snake_case")  // For JSON serialization (REST API)
@PropertyName("fieldNameCamelCase")      // For Firestore document mapping
private DataType fieldNameCamelCase;     // Java field name
```

**Example from existing code:**
```java
@JsonProperty("voltage_l1_v_min")
@PropertyName("voltageL1VMin")
private Double voltageL1VMin;
```

**For the new fields, follow this exact pattern:**

### Service Layer (No Changes Required)

**FunctionTestService Location:**
`smart-factory-backend/src/main/java/com/saijo/smartfactory/service/FunctionTestService.java`

The service methods are **field-agnostic** and will automatically handle new fields:

1. **addIndoorStandard(IndoorUnitStd standard)** (line 176-184):
   - Uses `docRef.set(standard).get()` which serializes ALL fields from the model
   - New fields will automatically be persisted to Firestore

2. **getIndoorStandard(String item)** (line 186-201):
   - Uses `document.toObject(IndoorUnitStd.class)` which deserializes ALL fields
   - New fields will automatically be populated from Firestore

3. **updateIndoorStandard(IndoorUnitStd standard)** (line 203-219):
   - Uses `document.getReference().set(standard).get()` which updates ALL fields
   - New fields will be included in update operations

**Why no service changes needed:** Firestore SDK uses Java reflection to serialize/deserialize POJOs. When new fields are added to the model with proper annotations, the SDK automatically includes them in all operations.

### Data Type Selection

**From PDF Analysis:**
- Indoor standard fields in PDF show string values: `"errorCode_max": "5"`, `"wifiStatus_max": "5"`
- These represent **thresholds or codes**, not numeric calculations
- Use `String` type to match PDF specification and maintain flexibility

**Type: String (not Integer/Double) because:**
1. PDF shows quoted string values
2. Error codes may be alphanumeric (e.g., "E01", "ERR_WIFI")
3. WiFi status may be text values ("Connected", "Loss" per IndoorUnitData model line 174)
4. Consistent with PDF contract expectations
