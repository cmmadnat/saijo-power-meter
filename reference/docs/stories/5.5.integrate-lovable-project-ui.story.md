## Technical Notes

### Integration Approach
- **Build Integration:** Update Quarkus pom.xml and deploy.sh to build and serve lovable-project instead of admin-ui
- **API Integration:** Modify lovable-project ApiService.ts to call real backend endpoints
- **UI Enhancement:** Add missing pages and functionality to match admin-ui feature set

### Existing Pattern Reference
- **Current Integration:** Admin-ui built via npm, copied to Quarkus META-INF/resources via maven-resources-plugin
- **Build Process:** deploy.sh handles frontend build and backend packaging
- **Static Serving:** Quarkus serves static files from META-INF/resources automatically

### Key Constraints
- Lovable-project must produce compatible build output (static HTML/JS/CSS)
- API calls must use relative paths (/api/v1/...) for same-origin requests
- UI must maintain all admin-ui functionality for seamless replacement

### API Endpoint Mapping
| Admin-UI Functionality | Backend Endpoint | Lovable-Project Implementation |
|------------------------|------------------|-------------------------------|
| Health check | GET /api/v1/health | ApiService health check |
| Function test data | GET /api/v1/function-test/* | Real API calls |
| Calorie meter | POST /api/v1/calorie-meter | Real API calls |
| EMC testing | POST /api/v1/emc | Real API calls |
