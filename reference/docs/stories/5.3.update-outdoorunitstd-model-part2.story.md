### Data Type Selection

**From PDF Analysis (pages 2-4):**
- PDF shows string values: `"compressorRpm_max": "3600"`, `"inverterDcVolt_max": "340"`, `"freshAirSupplyTemp_max": "26.5"`, etc.
- These represent **thresholds and configuration values**, not real-time measurements
- Use `String` type for consistency with Stories 5.1 and 5.2

**Type: String (not Integer/Double) because:**
1. PDF specification shows quoted string values
2. Maintains complete consistency with Story 5.2 pattern
3. Provides maximum flexibility for future requirements
4. Threshold/configuration values don't require numeric operations
5. Allows for potential non-numeric representations if needed in future

### Input Validation Guidance

**String Field Validation Considerations:**
- All 24 new String fields accept nullable values (optional in API requests)
- Fields are threshold/configuration values - no strict format validation required at model level
- Existing codebase does not enforce field-level validation on model objects
- Validation occurs at Resource layer (e.g., `item` field validation in FunctionTestResource)
- **Recommendation:** Follow existing patterns - no additional validation needed for these fields
- If future validation is required, it should be added consistently across all standard fields (existing + new)

**Note:** These fields represent configuration thresholds provided by domain experts. Business logic validation (if needed) would be implemented at the service or resource layer, not in the model.

### Service Layer (No Changes Required - Same as Stories 5.1 and 5.2)

**FunctionTestService Location:**
`smart-factory-backend/src/main/java/com/saijo/smartfactory/service/FunctionTestService.java`

The service methods for outdoor standards are **field-agnostic** (verified in Stories 5.1 and 5.2):

1. **addOutdoorStandard(OutdoorUnitStd standard)** (line 222-230):
   - Uses `docRef.set(standard).get()` which serializes ALL fields
   - New fields automatically persisted to Firestore

2. **getOutdoorStandard(String item)** (line 232-247):
   - Uses `document.toObject(OutdoorUnitStd.class)` which deserializes ALL fields
   - New fields automatically populated from Firestore

3. **updateOutdoorStandard(OutdoorUnitStd standard)** (line 249-265):
   - Uses `document.getReference().set(standard).get()` which updates ALL fields
   - New fields included in update operations

**Why no service changes needed:** Same reflection-based serialization pattern as Stories 5.1 and 5.2. The Firestore SDK automatically includes new fields when they're added to the model with proper annotations.
